# 登録有形文化財（建造物）

[国指定文化財等データベース](https://kunishitei.bunka.go.jp/bsys/index) (文化庁) から抽出した**登録有形文化財（建造物）**のデータ。
1 行 1 棟の JSON Lines で、都道府県ごとにファイルを分けてあります。

文化財分類コード 101 (登録有形文化財（建造物）) の全件です。

データは [heritage-crawler](https://github.com/shinyaoguri/heritage-crawler) が生成します。取得方法・スキーマの決定と
その根拠は、そのリポジトリの `docs/decisions/` にあります。

## 収録件数

**14,748 棟** / 48 ファイル (2026年8月12日時点)。

## データの形

```
data/<都道府県コード>_<ローマ字表記>.jsonl   例: data/29_nara.jsonl
```

- **1 行 1 棟。** キーは `(台帳ID, 管理対象ID)` = `ledger_id` と `managed_id` の組
- 行は上記のキーで安定ソートしてあります (取得順の揺れを差分に出さないため)
- 都道府県コードは JIS X 0401。都道府県で引けないものには 90 番台を割り当てて
  います (`90_multiple-prefectures` = 2 県以上にまたがる指定、
  `99_unspecified` = 地域を定めない)
- 値が空の項目はキーごと落としてあります (`null` も空文字も出しません)
- 日付は ISO 8601 (`2004-11-08`)。和暦は西暦の言い換えなので落としています
- 項目の集合は文化財の種別によって異なります。1 行に必ずあるのは
  `ledger_id` / `managed_id` / `category_name` / `url` と `designation_kind`

`url` はデータベースの詳細ページを指します。原文と突き合わせるときはそこを見て
ください。

## 更新

新規指定・登録は月次程度の頻度でしか起こらないため、更新も月次で行います。
更新の差分がそのまま「いつ何が変わったか」の履歴になります。
